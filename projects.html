PortfoliU, Optimal Portfolio Construction via Convex Optimization

A full stack platform that turns Markowitz mean variance theory into a solver, a backtester, and a product.

View Live Platform Source Code

Overview

PortfoliU began as a question that most retail investing tools quietly avoid. Given a universe of assets, what weights should an investor actually hold, and can that answer be defended mathematically rather than asserted? Modern portfolio theory answers this with convex optimization, so I built the platform around a real solver instead of a heuristic. A user selects a set of tickers, chooses an objective and a set of constraints, and the backend returns the optimal weight vector along with the efficient frontier that surrounds it.

What began as a coursework project inside the SEO Tech Developer Program grew into the piece of engineering I have spent the most time on. I led the backend, which meant owning the optimization engine, the risk models, the market data layer, the backtesting simulator, and the API contract that the React frontend consumes. The work was recognized as the strongest architectural design across every group in the program.

The Optimization Engine

The core of the system is a cvxpy program that solves eight distinct portfolio construction objectives. Minimum variance and target return are straightforward quadratic programs. Maximum Sharpe is not, because a ratio of a linear numerator to a quadratic denominator is non convex in the weights. The engine handles this with the Charnes and Cooper transformation, which exploits the scale invariance of the Sharpe ratio to rewrite the problem as an equivalent convex program in a rescaled variable. Conditional Value at Risk is formulated through the Rockafellar and Uryasev linear program, which turns a tail risk measure that looks combinatorial into something a solver can handle directly. Risk parity uses a convex log barrier reformulation, and maximum diversification and net of cost objectives round out the set.

Constraints matter as much as objectives. The engine supports long only portfolios, per asset weight bounds, sector exposure limits, turnover caps, and no trade bands, all of which map cleanly onto the convex formulation without breaking solver guarantees.

Risk Estimation

A mean variance optimizer is only as trustworthy as the covariance matrix it is handed. Sample covariance is notoriously ill conditioned when the number of assets approaches the number of observations, which produces optimal weights that are wildly sensitive to noise. PortfoliU therefore offers four estimators. Sample covariance is the baseline. Ledoit-Wolf shrinkage pulls the sample estimate toward a structured target and stabilizes the inverse. Exponentially weighted moving average estimation lets recent volatility dominate. A PCA factor model strips the estimate down to its leading components. Expected returns can be estimated directly from history or through Black-Litterman, which blends an equilibrium prior with subjective views.

Backtesting

Any optimizer looks brilliant when it is allowed to peek at the future. The backtesting engine runs walk forward, refitting the covariance and return estimates only on data available at each rebalance date, so lookahead bias never enters the simulation. Rebalancing cadence is configurable, transaction costs and turnover constraints are charged against the portfolio, and results are benchmarked against a broad index fund, an equal weight allocation, and a classic 60/40 split. The engine reports CAGR, Sortino ratio, Calmar ratio, alpha, beta, information ratio, and maximum drawdown rather than a single headline number.

Across a five year walk forward backtest the optimized portfolio beat every benchmark on risk adjusted return, delivering roughly 0.48 Sharpe against roughly 0.20 for the index fund, the equal weight portfolio, and the 60/40 allocation, with positive alpha and a lower maximum drawdown. The gap is not free money. It is what disciplined covariance estimation and cost aware rebalancing buy you once lookahead bias is removed from the evaluation.

Architecture

The backend is a FastAPI service using async SQLAlchemy against Supabase Postgres, with Redis caching in front of the market data layer so that repeated optimizations over the same universe never pay twice for the same price history. Market data flows through a pluggable provider interface. Financial Modeling Prep supplies real end of day pricing, and a deterministic synthetic provider stands in when no API key is present, which keeps the test suite hermetic and lets contributors run the stack cold. Authentication runs through Supabase with server side JWT verification against JWKS. Long running parameter sweeps execute as background jobs and stream their results to the client over WebSocket, rendering as an interactive Sharpe heatmap as the sweep fills in.

The frontend is React and TypeScript built with Vite, using TanStack Query to manage server state and Recharts to draw the efficient frontier, the weight allocations, the drawdown curves, and the live heatmap. Continuous integration gates every merge on linting across both halves of the stack and on eighty percent backend test coverage.
